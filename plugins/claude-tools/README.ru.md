# claude-tools

Плагин для Claude Code, который не даёт вашему 5-часовому окну лимитов начинаться в неудобный момент. Ставит cron, который шлёт один токен в Антропик и обновляет окно лимитов.

> 🇬🇧 [English version](README.md)

---

## Зачем?

Вы открываете Claude Code в 10:00. Начинаете работать. К 12:00 лимит закончился — Три часа простоя в середине рабочего дня. ДОСТАЛО!!!

А если бы вы открыли сессию в 07:00 — лимит закончился бы в 12:00 и сразу же открылось бы новое 5-часовое окно. С 06:00 до 16:00 можно работать **в двух окнах подряд**. Без простоев.

Окно стартует с **первого** запроса. Кто первым пинганул — тот и задал ритм.

Очевидное решение — поставить в cron `claude -p "ping"` каждые 5 часов, но это полумера. Да и не по вайбокодерски это:
- Свет отключили.
- Умер Wi-Fi.
- Ноутбук спал.
- На телефоне поставили? Так на телефоне интернет тоже не везде.
- Anthropic API недоступен 30 секунд — пинг провалился, до следующего ждать 5 часов.

Дамы и господа, предлагаем вам наше решение. С любовью, Claude Code 🩷

---

## Что делает плагин

Плагин ставит в crontab два задания. Первое — **сторож** — запускается каждый час, смотрит, когда вы последний раз пинговали Claude, и считает: окно живёт 5 часов, значит следующий пинг должен быть через столько-то. Сторож ставит второе задание — **точечный пинг** — ровно на нужную минуту.

Когда наступает время, точечный пинг просыпается, отправляет один токен в Claude и обновляет окно лимитов. Всё.

А что если в момент пинга **отрубилось питание / сеть / ноут спал**? Не страшно. Через час сторож снова проснётся, увидит: «эй, мы пропустили нужный момент» — и сразу запустит догоняющий пинг. Если и он не дошёл — внутри есть упорная цепочка из 11 повторов, размазанная на 4 часа: сначала через 5 секунд, потом через 15, потом раз в минуту, потом раз в час. Один из них точно прорвётся.

И последний предохранитель: если какой-то пинг намертво завис — через 4 с половиной часа его блокировка сама истечёт и не помешает следующему сторожу.

## Удаление

Запустите `/claude-tools:uninstall` (или `bash scripts/uninstall.sh`) **перед** удалением плагина — именно это снимает cron-задания. У Claude Code нет хука на удаление плагина, поэтому само по себе удаление плагина их не убирает.

На случай если забыли: начиная с **0.1.1** часовой сторож умеет залечивать себя сам — заметив, что файлы плагина исчезли, он снимает весь cron-блок claude-tools (включая себя) и останавливается. Так даже без ручного удаления cron вычистит себя в течение часа — **при условии, что сам скрипт-сторож ещё на месте**. Если каталог плагина исчез целиком (например, задание было поставлено версией 0.1.0 и указывает на старый путь кэша), сторож вообще не запустится — тогда удалите оставшиеся строки вручную через `crontab -e` или `bash scripts/uninstall.sh`.
